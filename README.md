# MTV 中文技术岗自我介绍

一个用于撰写和修改中文面试自我介绍的 Codex Skill，适合技术、工程、研发和制造岗位。

按照 **定位 → 成果 → 岗位价值** 组织内容，帮助候选人讲清楚自己的优势和实际贡献。表达保持专业、自然、严谨，避免机械念简历，也避免为了“像人说话”而过度口语化。

## 适用场景

- 已有一版自我介绍，但项目太多、重点不清楚。
- 需要根据新的岗位 JD 调整自我介绍。
- 结尾像复述岗位职责，没有说明自己能做什么。
- AI 改写后套话太多，或语气过于随意。

本技能专注于自我介绍，不承担完整模拟面试或整份简历重写。

## MTV 方法

这里的 MTV 沿用用户提供的方法名称，指以下三个问题，不对字母的英文含义作额外解释。

| 环节 | 回答的问题 | 写作要点 |
| --- | --- | --- |
| 定位 | 我是谁，主要擅长什么？ | 简短介绍背景，用有事实支持的能力定位留下印象 |
| 成果 | 我做过什么，结果如何？ | 选择 1—3 项相关成果，说明问题、个人动作和结果 |
| 岗位价值 | 这些经历对招聘方有什么用？ | 将已有经验连接到岗位中的具体工作 |

通常以一个主案例加一个辅助案例展开，其他经历按需要压缩。时长服从面试要求，不强制套用固定字数。

## 表达标准

保留必要的技术术语、工艺变量和验证结果，用具体动作代替空泛评价。

**偏机械：**

> 我理解该岗是连接产品研发、供应链和工厂的桥梁，我的经验具有可迁移性。

**过度口语：**

> 这类问题我接触过，有经验可以用上，也想把这块做好。

**本技能采用的表达：**

> 我过去做工艺验证时，需要分析缺陷原因、调整试验方案，再确认加工结果是否达到要求。这些经验可以用于岗位中的新工艺验证和样机问题分析。

以上仅为表达示例，不代表使用者的实际经历。

## 安装

将本仓库下载或克隆到 Codex 的个人技能目录，文件夹名称为 `mtv-self-introduction-cn`。

- 设置了 `CODEX_HOME` 时，放到其下的 `skills/mtv-self-introduction-cn`。
- 未设置时，放到用户主目录下的 `.codex/skills/mtv-self-introduction-cn`。

目录结构应为：

```text
mtv-self-introduction-cn/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── README.md
```

注意：`SKILL.md` 应直接位于技能文件夹内，避免下载解压后多嵌套一层目录。

## 使用

在 Codex 中明确调用技能，并提供原稿、目标岗位 JD 或真实项目经历。

### 修改现有自我介绍

```text
使用 $mtv-self-introduction-cn，结合下面的岗位 JD 修改我的自我介绍。
请保持技术岗需要的专业和严谨，避免机械套话，不要过度口语化。

目标岗位：……
岗位 JD：……
现有自我介绍：……
时长要求：……
```

### 从经历整理自我介绍

```text
使用 $mtv-self-introduction-cn，根据以下真实经历写一版中文面试自我介绍。
请选择与岗位最相关的项目，突出个人贡献，按定位、成果、岗位价值组织。

目标岗位：……
项目背景和问题：……
我负责的工作：……
已完成的结果：……
尚在验证的内容：……
```

默认输出一版可直接使用的完整稿件；需要短版或详细分析时，可另外提出。

## 事实边界

- 不编造指标、项目成果、企业需求或个人动机。
- 区分“参与”“负责”和“主导”，不扩大个人贡献。
- 区分已完成结果、正在验证的内容和未来计划。
- 不把工艺验证写成量产落地，不把调用外部模块写成自主开发。
- 保持技术指标原意，例如加工精度不能直接替代良率或一致性指标。
- 留下可继续讨论的项目细节，但不承诺控制面试提问或保证录用。

## 文件说明

- `SKILL.md`：选材、组织、语气和事实检查规则。
- `agents/openai.yaml`：显示名称、调用提示和自动选择设置。

技能本身不依赖 interview-coach 或 humanizer，也不包含个人简历、面试记录和账号信息。
